# CR Rules Summary - 输出格式模板

本文档定义 `cr-rules-summary.md` 的文件结构、Story 记录格式和单条规则格式。首次创建文件或追加规则沉淀记录时，必须严格按照此模板生成。

---

## 文件初始化模板

首次创建 `cr-rules-summary.md` 时使用以下骨架：

```markdown
# CR Rules Summary

用于沉淀跨 Story 可复用的 CR 规则提炼结果，记录规则来源、量化升格判定、适用范围、落地位置与同步状态。

---

## 规则索引

| 规则编号 | 标题 | 来源 Story | 总分 | 建议去向 | 同步状态 |
|----------|------|------------|------|----------|----------|

---

## Story 记录

<!-- 新 Story 规则沉淀记录追加在本章节下方，按日期升序或项目既有顺序排列。 -->
```

## Story 记录格式

每次完成一个 Story 的 CR 规则提炼并获得用户确认后，追加以下 Story 记录：

```markdown
### Story {story-id} / {YYYY-MM-DD}

- **Story**: {story-id}
- **分析来源**:
  - `{review-summary-file}`
  - `{review-evaluation-file}`
- **结论概览**:
  - {本 Story CR 历史中的关键发现、修复状态和可复用结论}

#### 升格判定摘要

| 候选规则 | 硬性门槛 | 总分 | 建议去向 | 用户确认结果 |
|----------|----------|------|----------|--------------|
| {rule-title} | 通过 / 未通过 | {N}/12 | global-doc / rules-summary / todo-tracker / none | {confirmed-result} |

### 提炼规则

#### {rule-id}：{rule-title}

- **来源问题**: {CR 中暴露的具体问题，包含触发条件和影响}
- **CR 证据**:
  - `{source-file}`: {summary / evaluation / fix record 中的证据摘要}
- **硬性门槛**:
  - 有证据: 是 / 否
  - 可规则化: 是 / 否
  - 非纯特例: 是 / 否
  - 不重复: 是 / 否
  - 状态明确: 是 / 否
- **量化评分**:

  | 维度 | 分数 | 理由 |
  |------|------|------|
  | 复现频次 | 0 / 1 / 2 | {理由} |
  | 影响范围 | 0 / 1 / 2 | {理由} |
  | 风险等级 | 0 / 1 / 2 | {理由} |
  | 根因稳定性 | 0 / 1 / 2 | {理由} |
  | 可执行性 | 0 / 1 / 2 | {理由} |
  | 文档缺口 | 0 / 1 / 2 | {理由} |

- **总分**: {N}/12
- **建议去向**: global-doc / rules-summary / todo-tracker / none
- **适用范围**: {技术栈、模块、流程或 Story 类型范围}
- **规避指南**:
  - {必须避免的做法}
- **最佳实践**:
  - {推荐做法、测试要求或检查点}
- **全局文档建议**:
  - {建议写入的文档、章节和写入方式；若不建议升格则写明理由}
- **本次落地**:
  - {已修复文件、已新增测试或不适用说明}
- **同步状态**: 未落地 / 已写入规则总结 / 已同步全局文档 / 交给 05 TODO Tracker / 不沉淀
```

## 单条规则字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 规则编号 | 是 | 建议格式为 `CR-{DOMAIN}-{NN}`，如 `CR-REPO-06`、`CR-TEST-01` |
| 标题 | 是 | 用一句话描述规则本质，避免只写现象 |
| 来源问题 | 是 | 写清 CR 发现的触发条件、影响和上下文 |
| CR 证据 | 是 | 至少引用 1 个 CR summary、evaluation 或 fix record |
| 硬性门槛 | 是 | 逐项记录通过/未通过，未通过不得升格 |
| 量化评分 | 是 | 6 个维度各 0-2 分，总分 12 分 |
| 建议去向 | 是 | `global-doc` / `rules-summary` / `todo-tracker` / `none` |
| 适用范围 | 是 | 标明适用技术域、模块、流程或限制条件 |
| 规避指南 | 是 | 明确禁止或应避免的行为 |
| 最佳实践 | 是 | 提供可执行做法、测试要求或检查点 |
| 全局文档建议 | 是 | 若建议升格，写明目标文档和章节；若不升格，写明理由 |
| 同步状态 | 是 | 记录最终落地状态，避免与 TODO backlog 重复管理 |

---

## 规则编号建议

- `CR-REPO-{NN}`: Repository、数据访问、迁移、持久化相关规则
- `CR-TEST-{NN}`: 测试 helper、fixture、mock、回归测试相关规则
- `CR-API-{NN}`: API 契约、接口兼容、请求响应相关规则
- `CR-DATA-{NN}`: 数据模型、数据一致性、序列化相关规则
- `CR-SEC-{NN}`: 安全、权限、敏感信息相关规则
- `CR-PERF-{NN}`: 性能、资源占用、并发相关规则
- `CR-PROCESS-{NN}`: CR 流程、分类分流、协作机制相关规则
- `CR-DOC-{NN}`: 文档、注释、开发指南相关规则
- `CR-OTHER-{NN}`: 无法归入以上类型的规则

编号按同一 domain 内已有最大编号递增，不复用已删除或已归档编号。

## 文档操作规范

### 首次创建

- 使用“文件初始化模板”创建 `cr-rules-summary.md`
- 初始化后再追加当前 Story 记录
- 规则索引必须同步填入本次新增规则

### 追加 Story 记录

- 新记录追加到 `## Story 记录` 下方
- 同一 Story 多次提炼时，应优先更新既有 Story 小节，而不是重复创建同名小节
- 若同一规则在后续 Story 中再次出现，应更新该规则的证据和复现频次，不重复创建等价规则

### 更新规则索引

- 每新增、更新或变更同步状态一条规则，必须同步更新 `## 规则索引`
- 索引中的“建议去向”和“同步状态”必须与规则正文一致

### 与 TODO Backlog 的边界

- `cr-rules-summary.md` 只记录已验证、已解决或已确认可沉淀的复用规则
- 未解决的非阻塞改进项应交由 05 TODO Tracker 管理，写入 `cr-todo-backlog.md`
- 同一事项不得同时作为 open TODO 和已沉淀规则重复管理；若 TODO 后续解决并形成规则，再从 TODO 的解决记录追溯到规则总结
