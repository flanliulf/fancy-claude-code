[Overview]
    Manages Skill version iteration. It analyzes changes, recommends a semantic version bump, synchronizes metadata.version in SKILL.md and SKILL.en.md, inserts a structured CHANGELOG.md entry, and syncs forge/ with all existing installed copies. Version rules are in `references/semver-guide.md`.

[Core Capabilities]
    - **Change analysis**: Read a user description or git diff, identify affected files and content, and classify changes as Added, Changed, Fixed, or Removed.
    - **Version recommendation**: Use `references/semver-guide.md` to recommend MAJOR, MINOR, or PATCH and explain the reason for user confirmation.
    - **Bilingual entry versioning**: Update metadata.version in both SKILL.md and SKILL.en.md.
    - **CHANGELOG maintenance**: Insert a newest-first changelog entry organized by Added, Changed, Fixed, and Removed.
    - **Multi-copy synchronization**: Detect and sync copies under forge/, `.claude/skills/`, `.agents/skills/`, and `.codex/skills/` when those roots actually exist.
    - **Mirror integrity**: Keep SKILL.en.md as an English mirror of the canonical Chinese SKILL.md, without missing capabilities, steps, constraints, or references.
    - **Quality loop**: Recommend skills-lint after upgrade completion.

[Workflow]
    This Skill follows a sequential workflow.

    Step 1: Locate target Skill
        Accept a Skill name or directory path. Search the source copy under forge/ and installed copies under `.claude/skills/`, `.agents/skills/`, and `.codex/skills/` when those roots exist. Read metadata.version from SKILL.md and SKILL.en.md, and latest version from CHANGELOG.md.

    Step 2: Analyze changes
        Collect change information from a user description, git diff, commit message, or "all changes since last changelog entry". Classify changes as Added, Changed, Fixed, or Removed.

    Step 3: Decide version
        Use the semantic version decision tree. Show current version, recommended version, bump type, and concrete reason. Wait for user confirmation before changing the version.

    Step 4: Update SKILL.md
        Update YAML metadata.version and preserve metadata.author and metadata.catalog.

    Step 5: Update SKILL.en.md
        Update metadata.version. If SKILL.en.md exists, mirror the changed SKILL.md sections in English. If it is missing, create it according to skills-creator mirror rules. Never update only SKILL.en.md without SKILL.md.

    Step 6: Update CHANGELOG.md
        Create the file if missing, or insert a newest-first version entry using only the non-empty Added, Changed, Fixed, and Removed categories.

    Step 7: Sync copies
        Detect source and installed copies. Use the user-modified copy as source; if only a Skill name is provided, default to forge/. Sync SKILL.md, SKILL.en.md, CHANGELOG.md, and any changed references/, scripts/, or assets/ files. Report missing roots without creating them.

    Step 8: Confirm completion
        Summarize the version change, updated files, synchronized copies, and recommend running skills-lint.

[Notes]
    - Version changes require user confirmation before execution.
    - CHANGELOG sections must use only Added, Changed, Fixed, and Removed.
    - Date format is YYYY-MM-DD.
    - New Skills start at 1.0.0 through skills-creator; later modifications use this Skill.
    - SKILL.md is the canonical Chinese entry with English-Chinese section headings; SKILL.en.md is an English mirror and cannot become the source of truth.
    - Sync per installed copy, and do not create missing install roots such as absent `.codex/skills/`.
    - Refuse requests to update CHANGELOG.md without updating metadata.version.
