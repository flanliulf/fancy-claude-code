# Skill Creation Workflow

## Overview（概述）

本文档承载 `skills-creator` 的详细创建流程。入口 SKILL.md 只保留阶段路由；执行创建时按本文档收集需求、规划结构、生成文件、运行 density gate 并总结交付。

## Requirement Collection（需求收集）

一次最多问 3 个问题。核心问题：
1. Skill 名称是什么？最终目录名自动转为 kebab-case。
2. Skill 要解决什么问题？核心功能是什么？
3. 什么时候触发？至少提供 3-5 个触发关键词，并覆盖中英文双语。

按需追问：
- 输入是什么：文件、参数、MCP 数据、其他 Skill 输出或用户上下文。
- 输出是什么：新文件、现有文件修改、分析结果或外部服务调用。
- 是否有明确执行步骤。
- catalog 是什么。已有参考：`skill-tooling`、`daily-work`、`ai-forge`、`bmenhance`、`speclite`。
- 是否需要 scripts/、references/ 或 assets/。

确认清单必须包含：
- Skill 名称和 kebab-case 目录名。
- 核心功能、触发场景和触发关键词。
- 输入、输出、catalog。
- 工作流模式和推荐理由。
- 文件结构草案。
- 是否需要脚本、reference 或模板。

## Structure Planning（结构规划）

先写入 forge/：
- 有 catalog：`forge/<catalog>/<skill-name>/`。
- 无 catalog：`forge/<skill-name>/`。

运行产物路径：
- 有 catalog：`output/<catalog>/<skill-name>/`。
- 无 catalog：`output/<skill-name>/`。

每个 Skill 至少包含：
- SKILL.md：中文 canonical 入口。
- SKILL.en.md：英文 mirror 入口。
- CHANGELOG.md：版本记录。

按需添加：
- references/：低频详细资料、复杂工作流、规则矩阵、示例说明。
- scripts/：确定性操作脚本，必须有 docstring、参数验证、错误处理和退出码。
- assets/：固定格式模板或资源。

禁止在 Skill 目录创建 README.md。

## Entry Generation（入口生成）

SKILL.md：
- YAML 包含 name、description、allowed-tools 和 metadata 字段契约。
- `metadata.version` 与 `metadata.author` 必填；`metadata.catalog` 仅在归入 catalog 时填写，并与输出路径及 SKILL.en.md 对齐。
- 不生成未登记的 `metadata.*` 字段。
- description 使用英文三段式，触发词覆盖中英文。
- 正文内容使用中文。
- 章节标题使用 English（中文）形式。
- 命令、路径、字段名、fixture 名称、schema/issue id、API、库名、协议名等技术标识使用英文。

SKILL.en.md：
- YAML 与 SKILL.md 保持一致。
- 英文正文 mirror SKILL.md。
- 不新增或删除能力、步骤、限制、引用路径和触发边界。
- 若两者冲突，以 SKILL.md 为 canonical 来源。

CHANGELOG.md：
- 初始版本为 1.0.0。
- 日期使用 YYYY-MM-DD。
- 从 Core Capabilities 提取初始功能清单。
- 如有已知限制，写入已知问题。

## Workflow Density Gate（Workflow 密度门禁）

生成草稿后运行 deterministic checker，不得用 LLM 估算：

```bash
python3 forge/skill-tooling/skills-lint/scripts/check_skill_density.py <skill-dir>
```

如果在安装副本中执行，可使用对应 `skills-lint/scripts/check_skill_density.py`。

脚本字段含义：
- `body_chars`：正文字符数。
- `workflow_chars`：Workflow 章节字符数。
- `workflow_ratio`：Workflow 占正文比例。
- `near_body_limit`：正文是否达到 4500 字。
- `has_workflow_reference`：入口是否引用 workflow reference。
- `triggered_density_warning`：`workflow_chars > 1500` 且 `workflow_ratio > 0.5`。

命中 `triggered_density_warning` 时：
- 创建 `references/<skill-name>-workflow.md` 或等价 workflow reference。
- 将详细步骤、命令清单、规则矩阵、长校验列表、示例和边界条件移入 reference。
- 入口 Workflow 只保留阶段摘要、何时读取 reference、关键停止条件。
- SKILL.md 和 SKILL.en.md 必须引用同一 workflow reference 路径。

## Generation Metadata（生成标注）

SKILL.md 末尾追加：

```text
[Generation Metadata（生成信息）]
    本 Skill 由 skills-creator 自动生成。如需修改，必须同步更新 SKILL.md 与 SKILL.en.md，并同步 forge/ 与实际安装副本，或通过 skills-upgrade 管理版本。
```

SKILL.en.md 末尾追加：

```text
[Generation Metadata]
    This Skill was generated by skills-creator. Update SKILL.md and SKILL.en.md together, and sync forge/ with installed copies or manage versions through skills-upgrade.
```

凡 Skill 会写入运行产物，必须在其输出文档末尾追加：

```text
---

*本文档由 <skill-name> Skill 自动生成*
```

## Completion（完成总结）

交付时输出：
- 完整文件树。
- 渐进式披露分层说明。
- 如何使用：重启智能体并使用触发关键词。
- 三类触发测试建议：明确相关、同义替换、无关查询。
- 建议运行 `skills-lint` 和后续 `skills-upgrade`。

## Error Handling（错误处理）

- 名称含大写、空格或下划线：转换为 kebab-case 并告知用户。
- description 超过 1024 字符：精简后提示用户确认。
- 正文超过 5000 字符：拆分低频内容到 references/。
- `git config user.name` 读取失败：请求用户提供 author。
- 安装根不存在：只报告未发现，不创建新的安装副本。
