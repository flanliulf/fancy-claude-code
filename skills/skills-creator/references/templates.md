# 生成模板

## 概述
本文档包含 Skill 包各类文件的标准生成模板，用于在文件生成阶段按模板创建文件内容。

## SKILL.md 模板（中文 canonical）

```markdown
---
name: <kebab-case-skill-name>
description: "<功能描述>. <触发条件，含关键词和文件类型>. <核心能力说明>"
allowed-tools: <根据 allowed-tools 判断规则自动选择>
metadata:
  version: "1.0.0"
  author: "<author-name>"
  catalog: "<catalog-name>"  # 可选；填写时必须与路径和 mirror 对齐
---

[Overview（技能说明）]
    <一句话概括 Skill 的价值和能力，突出为什么需要这个 Skill>

[Core Capabilities（核心能力）]
    - **<能力 1>**：<能力描述>
    - **<能力 2>**：<能力描述>
    - **<能力 3>**：<能力描述>
    <根据 Skill 复杂度列出 4-8 个核心能力>

[Workflow（执行流程）]
    <根据匹配的工作流模式设计流程结构，参考 references/workflow-patterns.md>
    <若 Workflow density gate 命中，仅保留阶段摘要、何时读取 references/<skill-name>-workflow.md、关键停止条件>

[Notes（注意事项）]
    - <关键约束和边界条件>
    - <质量标准和验证要求（具体化，不用模糊词）>
    - <特殊场景的处理说明>
    - <与其他 Skills 的协作方式（如果适用）>
    - <已知限制和边界情况>

[Generation Metadata（生成信息）]
    本 Skill 由 skills-creator 自动生成。如需修改，必须同步更新 SKILL.md 与 SKILL.en.md，并同步 forge/ 与实际安装副本，或通过 skills-upgrade 管理版本。
```

### SKILL.md 语言规则

- SKILL.md 是中文 canonical 文档，正文内容始终使用中文。
- 章节标题必须使用 English（中文）形式，例如 `[Overview（技能说明）]`、`[Core Capabilities（核心能力）]`、`[Workflow（执行流程）]`、`[Notes（注意事项）]`。
- 命令、路径、字段名、fixture 名称、schema/issue id、API 名称、库名、协议名等技术标识以及专有技术术语使用英文。
- 不在中文正文中翻译已经稳定的技术标识，例如 `metadata.version`、`allowed-tools`、`references/`、`scripts/`、`CHANGELOG.md`。

### metadata 字段契约

- `metadata.version` 必填，使用 SemVer，并与 SKILL.en.md 和 CHANGELOG.md 最新版本一致。
- `metadata.author` 必填，记录原始作者，升级时保持稳定。
- `metadata.catalog` 可选；当 Skill 归入 catalog 目录时填写，值使用 kebab-case，并与路径和 SKILL.en.md mirror 一致。
- 不生成未登记的 `metadata.*` 字段；确需新增字段时，先同步更新 creator、lint 和 upgrade 的字段契约。

## SKILL.en.md 模板（英文 mirror）

```markdown
---
name: <kebab-case-skill-name>
description: "<same description as SKILL.md>"
allowed-tools: <same allowed-tools as SKILL.md>
metadata:
  version: "1.0.0"
  author: "<author-name>"
  catalog: "<catalog-name>"  # optional; must align with path and SKILL.md when set
---

[Overview]
    <English mirror of SKILL.md Overview. Keep the same capability boundary.>

[Core Capabilities]
    - **<Capability 1>**: <English mirror of capability 1>
    - **<Capability 2>**: <English mirror of capability 2>
    - **<Capability 3>**: <English mirror of capability 3>
    <Mirror the 4-8 capabilities from SKILL.md in the same order.>

[Workflow]
    <English mirror of SKILL.md Workflow. Keep steps, inputs, outputs, references, and stop conditions aligned.>
    <If Workflow density gate is triggered, keep only phase summary, when to read references/<skill-name>-workflow.md, and stop conditions.>

[Notes]
    - <English mirror of key constraints and boundaries>
    - <English mirror of concrete quality and validation requirements>
    - <English mirror of edge cases and known limitations>

[Generation Metadata]
    This Skill was generated by skills-creator. Update SKILL.md and SKILL.en.md together, and sync forge/ with installed copies or manage versions through skills-upgrade.
```

### SKILL.en.md mirror 规则

- SKILL.en.md 必须与 SKILL.md 同步生成，不得省略。
- YAML frontmatter 的 `name`、`description`、`allowed-tools`、`metadata.version`、`metadata.author`、`metadata.catalog` 必须与 SKILL.md 保持一致。
- 英文正文必须是 SKILL.md 的语义 mirror，不能新增或删除能力、步骤、限制、引用路径和触发边界。
- 如果更新 SKILL.md，必须同步更新 SKILL.en.md；如果信息存在冲突，以 SKILL.md 为 canonical 来源。

### Workflow density gate

生成 SKILL.md 与 SKILL.en.md 草稿后，必须运行 deterministic checker，不得由 LLM 估算：

```bash
python3 forge/skill-tooling/skills-lint/scripts/check_skill_density.py <skill-dir>
```

固定阈值：
- `workflow_chars > 1500`
- `workflow_ratio > 0.5`
- `near_body_limit` 为 `body_chars >= 4500`

任一入口文件命中 `triggered_density_warning` 时：
- 新增 `references/<skill-name>-workflow.md` 或等价 workflow reference。
- 将详细步骤、规则矩阵、命令清单、长检查列表和示例移入 reference。
- SKILL.md 与 SKILL.en.md 的 Workflow 只保留阶段路由、何时读取 reference、关键停止条件。
- 两个入口必须引用同一个 workflow reference 路径。

### description 生成规则

必须使用三段式结构（不超过 1024 字符）：
1. 功能描述（What it does）：做什么
2. 触发条件（When to use it）：何时用 + 关键词（中英文双语）+ 文件类型
3. 核心能力（Core capabilities）：擅长什么

**绝对禁止在 description 中出现 `<` 或 `>` 符号！**
**触发关键词必须同时包含中英文常用表述，确保双语用户都能触发！**

示例：
```
"Convert CSV files to Markdown tables with Chinese encoding support. Use when user mentions 'CSV', 'convert', 'markdown', 'table', 'CSV 转换', '表格转换', 'Markdown 表格', uploads .csv files, or wants to format tabular data. Capable of handling multi-encoding detection, large file splitting, and custom column formatting."
```

## CHANGELOG.md 模板

```markdown
# Changelog

本文件记录 `<skill-name>` 技能的版本变更历史。

格式基于 [Keep a Changelog](https://keepachangelog.com/)，版本号遵循 [Semantic Versioning](https://semver.org/)。

## [1.0.0] - <YYYY-MM-DD>

### 初始版本

- <核心能力 1>
- <核心能力 2>
- <核心能力 3>
<从 SKILL.md 的 [Core Capabilities（核心能力）] 提取>

### 已知问题

- <已知限制或问题>（如果有）

---

版本变更类型说明：
- **Added**：新增功能
- **Changed**：已有功能的变更
- **Fixed**：缺陷修复
- **Removed**：移除的功能

后续版本更新时，在 [1.0.0] 之前插入新版本记录，并同步更新 SKILL.md 与 SKILL.en.md 中的 metadata.version。
已知问题修复后，用删除线标注并注明修复版本，如：
- ~~**问题描述**~~ → 已在 vX.Y.Z 修复
```

```markdown
<简要说明本文档的内容和用途>

<具体内容，使用表格、代码块、列表等合适的格式>

## <内容分类 2>
<具体内容>

## <内容分类 3>
<具体内容>

## 版本说明
- v1.0 (YYYY-MM-DD): 初始版本

<根据实际需求组织内容结构>
```

## Script 脚本规范

放置位置：`scripts/` 子目录

脚本必须包含：
- 清晰的文件头 docstring（功能说明、用法、示例）
- 合理的参数设计
- 适当的错误处理（try-except 捕获常见异常）
- 正确的退出码（成功返回 0，失败返回非 0）
- 合适的输出格式（JSON/文本/CSV 等）
- 输入验证（检查文件存在性、参数合法性等）

## Assets 模板规范

放置位置：`assets/` 子目录

模板文件要求：
- 格式统一
- 占位符使用 `{placeholder_name}` 格式，清晰标注
- 包含完整的章节结构
- 如果是 Markdown 模板，可包含 YAML frontmatter
