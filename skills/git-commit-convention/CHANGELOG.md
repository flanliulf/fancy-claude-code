# Changelog

本文件记录 `git-commit-convention` 技能的版本变更历史。

格式基于 [Keep a Changelog](https://keepachangelog.com/)，版本号遵循 [Semantic Versioning](https://semver.org/)。

## [1.4.0] - 2026-03-29

### Added

- Commit Message 描述语言选择交互：在 Step 2 分组判断之前新增语言确认环节
- 默认语言改为中文：简短描述默认使用中文陈述句（如"添加用户认证功能"）
- 用户可选择英文：切换后使用英文祈使句（如 "add user authentication"）
- 语言边界说明：类型（feat/fix 等）、范围（scope）和 BREAKING CHANGE 标记始终使用英文，语言选择仅影响冒号后的描述部分

### Changed

- 工作流从"分析→生成→确认→提交→推送"调整为"分析→语言选择→分组生成→确认→提交→推送"
- 分组结果示例从英文描述更新为中文描述（作为默认示例）
- 注意事项中描述语言规则从"固定英文祈使句"更新为"默认中文，支持切换英文"

## [1.3.0] - 2026-03-28

### Added

- 融合原 /git:gcp 斜杠命令：提交完成后可选推送到远程仓库
- 意图识别：根据用户表述中的关键词（'gcp'、'push'、'推送' 等）自动判断是否需要推送
- 推送前三项安全检查链：
  · 检查 1：远程仓库是否存在（`git remote -v`，纯本地仓库自动跳过）
  · 检查 2：当前分支是否有远程跟踪（无则自动 `git push -u`）
  · 检查 3：目标分支保护（main/master 需用户二次确认）
- 推送失败处理：冲突时建议 `git pull --rebase`，绝不 force push
- 触发词扩展：新增 'gcp'、'push'、'commit and push'、'提交并推送'、'推送到远程'、'同步远程'

### Changed

- 推送策略从"绝不 push"改为"默认不 push，用户表达 push 意图时条件性执行"
- 工作流从"分析→生成→确认→提交"扩展为"分析→生成→确认→提交→推送（可选）"

## [1.2.0] - 2026-03-28

### Added

- 四层分组判断架构：基础设施分离 → Story 分组 → 类型判断 → 大 Story 拆分
- Story 优先分组：同一 Story 产生的代码、测试、CR 文档、全局文档连带变更归为一次提交
- 多 Story 强制拆分：不同 Story 的变更必须独立提交，禁止跨 Story 合并
- 基础设施独立提交：.gitignore、CI 配置、IDE 配置等与业务无关的文件始终单独成组
- 两个详细分组示例：单 Story + 基础设施混合、多 Story 并存

### Changed

- 分组优先级从"按类型分组"重构为"Story 优先 → 基础设施独立"策略
- 提交顺序从"基础设施→功能→测试→文档"调整为"基础设施→各 Story（按 ID 升序）"
- 同一 Story 内的功能代码 + 文档 + 测试合并为一次提交（而非按类型拆开）

## [1.1.0] - 2026-03-28

### Added

- 多变更分组提交：当变更涉及不同提交类型或不同业务域时，自动按类型+模块分组，生成多条 commit message 并分批提交
- 分组判断规则：按提交类型分组 → 同类型内按业务域/模块再分组 → 同域同意图合并
- 提交计划展示：多分组时以编号列表展示完整提交计划，供用户确认或调整
- 分批提交顺序：按"基础设施 → 功能代码 → 测试 → 文档"排序，优先提交被依赖的内容
- 提交失败熔断：某次提交失败时立即停止后续提交，等待用户处理

### Changed

- 多变更拆分从"建议"升级为"强制规则"，禁止将不相关变更合并为一次提交

## [1.0.0] - 2026-03-28

### 初始版本

- 变更摘要分析：通过 git diff/status 全面分析暂存区和工作区的代码变更
- 提交类型判断：自动匹配 Conventional Commits 规范的 11 种提交类型
- 范围自动提取：从变更文件路径推断合理的 scope
- 破坏性变更检测：识别潜在 BREAKING CHANGE 并自动标记
- Commit Message 规范生成：严格按照约定式提交格式生成
- 安全提交：提交前检查敏感文件，避免误提交 .env、credentials 等
